# OctoAcme Project Management Docs

This folder contains OctoAcme's project management guidance. Use the links below to find the process or role information you need.

## Project management at a glance

OctoAcme follows a project lifecycle of initiation, planning, execution, release, and retrospective. Initiation validates the business need, measurable outcomes, stakeholders, risks, resources, and whether work is ready to proceed. Planning turns approved work into prioritized, estimated increments with acceptance criteria, ownership, dependencies, milestones, and a Definition of Done.

During execution, teams track work on a project board, deliver in small increments, and surface risks and blockers early. The Project Manager coordinates delivery, schedules, risks, and communications; the Product Manager defines outcomes, prioritizes the backlog, and measures impact. Developers build and test the work, QA validates acceptance, and stakeholders provide input and approvals.

Regular standups, weekly delivery syncs, and stakeholder updates keep work aligned. Blockers are triaged by the team and escalated through the Project Manager and Product Lead to the sponsor when needed. Quality practices include unit tests for new logic, integration tests where applicable, smoke tests for critical flows, and pull requests that link issues and acceptance criteria and pass CI, linting, and security scans before review. Releases include pre-release checks, deployment verification, and rollback or incident procedures; retrospectives turn lessons into owned, trackable improvements.
